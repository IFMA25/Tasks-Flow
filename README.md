# ✅ Tasks-Flow – веб-додаток для керування задачами

Веб-додаток для керування задачами та списками з акцентом на UX, продуктивність та реалістичні сценарії використання (особисті задачі, робочі тудушки, щотижневі цілі).

---

## 🛠 Стек технологій

- **Фреймворк:** Vue 3 (Composition API, `<script setup>`)
- **Мова:** TypeScript
- **Стан:** Pinia (`defineStore`)
- **Маршрутизація:** Vue Router
- **HTTP/API:** власні composable‑хуки (`useTasksRequest`, `useDashboardRequests` тощо)
- **UI:**
  - кастомні компоненти (`VTable`, `VCheckbox`, `VButton`, `VActionsDropdown`, `VCollapseContainer`)
  - skeleton‑компоненти для завантаження (`TasksTableSkeleton`, `SkeletonWeeklyGoals`)
- **Дата/час:** `date-fns` для форматування дат
- **Локалізація:** `vue-i18n`
- **Нотифікації:** `vue-sonner` для показу повідомлень про помилки
- **Деплой:** GitHub Pages + GitHub Actions, конфіг через `VITE_` змінні оточення
- **Пакетний менеджер:** pnpm

## 🚀 Запуск локально

```bash

VITE_SUPPORTED_LOCALE=en,uk

pnpm run dev
```

## 🧠 Робота з API та кешування

- Усі HTTP‑запити до бекенду виконуються через окремі composable‑хуки (для задач, дашборда, аналітики тощо), що ізолює логіку запитів від UI.
- Для повторюваних запитів використовується кешування даних:
  - повторні переходи на сторінку не викликають зайвих запитів;
  - стан списків задач і дашборда оновлюється тільки тоді, коли це дійсно потрібно (створення/оновлення/видалення).
- Оновлення даних виконуються точково (інвалідація кешу після змін), що робить UI відчутно швидшим.

## 🔐 Автентифікація

- Логін та реєстрація користувачів
- Автоматичне перенаправлення на головну сторінку після успішного входу
- Захищені маршрути: доступ до сторінок тільки для авторизованих користувачів
- Автоматичний рефетч сесії / користувача

---

## 📊 Dashboard

- Перегляд актуальних задач на сьогодні та найближчі дні
- Блок щотижневих цілей:
  - вибір задач як “цілей на тиждень”
  - відмітка виконання прямо з дашборда
  - статус задачі синхронізується зі сторінкою списків

---

## 🧾 Списки задач

- Створення власних списків задач
- Перегляд “моїх списків” та “списків користувачів” (залежно від прав доступу)
- Редагування та видалення списків

---

## ✅ Задачі

- Створення, редагування та видалення задач
- Статуси: `todo` / `done`
- Пріоритети: `low` / `medium` / `high`
- Теги для групування задач
- Дедлайни з календарем для зручного вибору дати

---

## 🔍 Фільтри, пошук та сортування

- Сортування задач за:
  - датою створення (нові / старі)
  - за назвою (A → Z / Z → A)
- Фільтрація задач за пріоритетом:
  - усі / low / medium / high

- Сортування списку користувачів за:
  - ім'ям користувача (A → Z / Z → A)
  - датою створення (нові / старі)
  - роллю користувача
- Пошук користувачів за ім'ям

- Сортування списків задач за:
  - датою створення та оновлення
- Пошук списків за назвою

---

## ⚡ Статуси задач з оптимістичним UI

- Натискання на чекбокс одразу змінює стан задачі в UI (без очікування відповіді сервера)
- Якщо запит до API падає:
  - показується повідомлення про помилку
  - дані синхронізуються з бекендом (стан повертається до фактичного)

---

## 📂 Активні та виконані задачі

- Окремі блоки:
  - “Pending” — активні задачі
  - “Completed” — виконані задачі
- Кожен блок:
  - таблиця задач із чекбоксом статусу
  - пріоритет
  - дедлайн
  - теги
  - (для активних задач) дії через дропдаун

---

## 🔑 Права доступу та дії

- Гнучка система прав (`permissions`) на основі ключів типу
- Перевірка прав у UI
- guard‑логіка для захисту маршрутів за роллю / правами

---

## 🌍 Локалізація

- Підтримка кількох мов через `vue-i18n` (en, uk)
- Усі тексти, заголовки, лейбли та повідомлення беруться з i18n‑словників

---

## 📈 Аналітика

- Графік створених та виконаних задач за тиждень та місяць
- Кругова діаграма з кількістю задач за пріоритетами
- Гістограма використання тегів (частота / кількість задач з тегом)

---

## 🛡️ Адмін‑панель

- Перегляд усіх користувачів
- Редагування та видалення користувачів
- Надання прав адміністратора та зміна прав доступу користувачів

---

## 👤 Демо‑користувач

- Для швидкого входу використовується тестовий користувач (демо‑акаунт)
- Облікові дані демо‑користувача прокидаються через `VITE_` змінні оточення (GitHub Actions secrets) і не зберігаються в репозиторії
